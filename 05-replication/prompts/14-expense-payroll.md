# M7 费用审批、工资与资产台账

> 本页是复刻路线图 M7 阶段的第二篇 prompt:把报销/付款/备用金审批、月度工资、以及固定资产台账建进自己的系统,并让它们的产出直接变成会计凭证。适合已完成 M5 内账引擎的团队,以及他们的 AI 编程助手。

## 读完你会知道

- 为什么这三件事放在同一篇:它们都是「单据 → 凭证」的上游
- 类别下拉即会计科目、审批链快照、付款确认时入账,这三条怎么写进 prompt
- 工资模块的分界线:档案承载不变量,浮动一律走申报
- 一份验收清单,重点验的是**入账失败时会不会静默**

## 目标

- **费用单**:报销、付款申请、备用金借还,全流程在自己系统里走完,付款确认时自动生成凭证;
- **工资**:薪资档案 + 绩效申报 + 月度工资单,确认即计提,付款事实确认后出发放凭证;
- **资产台账**:实物档案 + 领用流转 + 维保 + 保养提醒,与财务折旧卡片单向关联。

背景模式篇见[费用审批与工资](../../02-modules/expense-payroll.md)与[资产台账](../../02-modules/asset-management.md)。

## 喂给 AI 的指令

整块复制给你的 AI 编程助手,先替换方括号占位符。

```markdown
你要在现有 Django 单体项目(已完成内账引擎)里,新增费用单、工资与资产台账三个模块。

## 模块一:费用单(报销 / 付款申请 / 备用金)

模型:
1. 费用单(ApplyOrder):业务类型(报销/付款/备用金/归还)、申请人、区域、部门、
   金额、类别、收款人、附件、状态、审批链快照、付款账户、来源凭证号、入账错误信息;
2. 类别(ApplyCategory):**从会计科目表镜像出来的费用类末级科目**,
   同名科目加后缀区分;申请人只能从这里选,禁止自由文本;
3. 审批链(ApplyFlow):按 (业务类型, 区域, 金额阈值) 配置审批人序列;
   匹配优先级 = 精确(类型+区域) > 类型兜底 > 全局兜底,**必须保留一条全局兜底链**;
4. 审批日志(ApplyLog):每一步操作留痕。

规则:
- 提交时把命中的审批链**快照**进单据,之后配置变更不影响在途单;
- 入账时点 = **付款确认**(收付实现),不是审批通过;
  例外:报销勾选「冲抵备用金」时,终审通过即入账(贷记备用金);
- 生成凭证以单号为业务键**幂等**;入账失败**不回滚付款状态**,
  错误写入单据的错误字段,可重试;
- ★付款确认时必须选到**具体的一张卡**(科目 × 账户),不能只选科目——
  银行存款按账户做辅助核算,只存科目会导致凭证生成必然失败;
  可选卡列表要排除已停用账户和不属于本主体的账户;
- 辅助核算维度只允许 [区域/部门/员工/供应商/账户] 这几种,
  新建科目若需要系统补不出的维度,提交时直接拦截并提示。

## 模块二:工资

模型:
1. 薪资档案(PayrollProfile):员工、底薪、社保/公积金基数、申报工资、薪资主体、
   固定项列表[{名称, 金额}]、特殊覆盖值(锁定个人/公司社保金额);
2. 绩效申报(PayrollPerf):被申报人、期间、多个明细项(内容/金额/备注)、审批链快照;
3. 月度工资单(PayrollMonth):期间、明细行(底薪+固定项+已批绩效−个人代扣=实发)、
   状态、计提凭证号、发放计划;
4. 发放计划(PayrollPayPlan):按 [主体 × 对公/私卡] 分笔,每笔各配账户与凭证号。

规则:
- **档案只放每月不变的量,浮动一律走绩效申报**;
- 工资单确认 → 生成**计提凭证**(费用/生产成本 vs 应付职工薪酬),
  部门决定是否计入生产成本,部门必须是**受控词表**,不得自由文本;
- 发放:① 有流水的账户跑定时匹配任务,在发薪窗口内找金额**精确相等**的付款流水,
  命中即出发放凭证;② 无流水的账户提供手工「已转账,生成发放凭证」按钮——
  **手工路径是主路径,自动匹配是加速器**;
- 兼职/临时用工不得进入工资模块,走费用单的劳务费类别。

## 模块三:资产台账

模型:资产档案(编号/类别/型号/位置/责任人/铭牌照片/财务卡片ID)、
领用流转记录、维保记录、保养计划(下次到期日 + 提前天数)。

规则:
- 人员字段存 **ID + 姓名快照**,不用裸外键;
- 资产编号**自己发号**,不依赖厂商序列号(同型号设备的出厂码可能重复);
- 提供「一键生成财务卡片」,按类别带出折旧年限,之后两侧互不混写;
- 扫码页:每台设备生成带**签名令牌**的二维码 URL,免登录访问,
  作用域仅限该设备,可登记维保与一键报修;报修后置状态并通知责任人;
- 保养提醒定时任务:临期限频提醒、逾期每天提醒,发**单聊**不发群;
- ★维修费**不自动生成凭证**——费用入账只走费用单一个入口,防重复过账;
- 免登页所有请求必须有非 JSON 响应的兜底处理。

## 接口与工程约定

- 沿用 M1 响应格式与鉴权;金额一律 Decimal;
- 费用/工资接口挂财务权限;资产台账登录即可用,财务卡片关联需资金权限;
- 三个模块的所有凭证生成一律调用内账引擎的唯一出口 service。

## 红线

- 类别下拉必须是科目镜像,不允许自由文本;
- 审批链提交即快照;
- 凭证幂等、失败留痕、失败不回滚业务状态;
- 同一笔钱只能有一个入账入口;
- 不放任何真实薪酬、金额或人名到代码与测试数据里。
```

## 验收清单

- [ ] **类别即科目**:新增一个费用科目后,费用单的类别下拉自动出现它,无需改代码
- [ ] **审批链快照**:提交一张单后修改审批链配置,该单的后续审批仍按提交时的链走
- [ ] **入账时点**:审批通过但未付款的单据,账上没有凭证;付款确认后凭证出现且日期等于付款日
- [ ] **入账幂等**:重复调用付款确认,只生成一张凭证
- [ ] **失败不静默**:故意让某单缺辅助维度,付款状态仍成功、单据上有明确的入账错误信息、修复后重试成功
- [ ] **付款卡到账户**:付款确认时只能选到具体账户;已停用账户不在选项里
- [ ] **工资分界线**:调整某员工的浮动绩效,薪资档案零改动;调整社保基数,对公金额自动跟随
- [ ] **计提/发放两段**:工资单确认后应付职工薪酬挂账;确认发放后挂账清零
- [ ] **多笔发放**:一张工资单可以分成多笔发放计划,各自匹配各自的账户
- [ ] **资产扫码免登**:用签名令牌打开的页面只能看到该设备,篡改令牌被拒;接口异常时页面不白屏
- [ ] **保养提醒**:临期设备按限频提醒、逾期设备每天提醒,消息发到责任人单聊
- [ ] CLAUDE.md 已更新

## 踩坑与红线

- **症状**:凭证生成永远失败,业务侧看不出原因。
  **根因**:银行存款科目要账户维度,单据上只存了科目。
  **铁律**:付款要选到卡;带辅助核算的科目必须在单据上有对应落点。

- **症状**:办公室人员的工资被计入了生产成本。
  **根因**:部门判断靠名称关键词,而部门名是自由文本。
  **铁律**:部门是受控词表,且与期初挂账口径一致。

- **症状**:自动匹配永远不命中,发薪流程卡死。
  **根因**:该账户的流水根本不在系统里,却把自动匹配当成了唯一路径。
  **铁律**:主路径必须手工可完成,自动化是加速器。
