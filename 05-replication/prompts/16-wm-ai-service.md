# M8 线上客服 AI:代回、紧急电话与控制台

> 本页是复刻路线图 M8「AI 接管一线」的第一篇 prompt:让 AI 接住三个外卖平台上的顾客消息——起草并代回、该交人的交人、真紧急的打电话问门店老板,再给值班客服一个控制台和一条「标记 → 改规则 → 回放 → 生效可回滚」的优化闭环。适合已完成 M4 的 07(外卖平台集成)与 M6 的 12(群聊机器人)的团队,以及他们的 AI 编程助手。

## 读完你会知道

- 最小可用形态是什么:先影子起草、再限额真发、最后才上电话和自动优化
- 为什么「发送前一刻终检」和「确定性守卫在模型之后」是这个模块的两根承重墙
- 涉钱、承诺、红线三类事怎么写成 AI 绕不过去的约束
- 一份验收清单,重点验的是**AI 该停的时候停没停**

## 目标

建成一套**线上客服 AI**:

- 顾客消息按轮切分;值班外 AI 先回、值班内超时兜底;高风险意图走固定模板 + 转门店群;
- 已交人工的会话在平台考核时限前补一句安抚,过时限不迟发;
- 紧急事件给门店老板打对话式电话,只认本人口头确认,涉钱一律转人工;
- 值班客服控制台:回复率、当前待回、待办、电话、发送失败与撤回、排班与交接班;
- 「待优化」闭环:人标真值 → AI 出候选规则 → 回放 → 自动生效或老板拍板 → 跟踪 → 可回滚。

背景模式篇见[线上客服 AI:顾客消息代回、紧急电话与「待优化」闭环](../../02-modules/wm-ai-service.md),建议先读再喂 prompt。

## 喂给 AI 的指令

整块复制给你的 AI 编程助手。方括号内的占位符先替换成你的实际参数。

```markdown
你要在现有 Django 单体项目里新增「线上客服 AI」模块。按下面的顺序施工,每一步做完先自检再进下一步。
★全程默认影子:一切对外动作(发消息、拨电话、转群、推个人微信)都要有
总开关 + 按平台开关 + 限额;开关关闭时只落库、不发出。

## 第一步:口径文档先行

先产出「线上客服口径文档」草案,交人类确认后再写代码。必须写清:
1. 「一轮」的定义:顾客连续消息归为一轮,任何一方回复即切轮;
   我方发给骑手的转达消息不切轮、不算「回复了顾客」;
2. 在班口径:按排班表判断(当班 / 顶班 / 无人值班),无人值班等同不在班;
3. 等待时长:在班时首条后 [示例:4 分钟] 无人回才兜底;不在班时顾客安静 [示例:20 秒] 即回;
4. 意图清单与处置:哪些走模型起草,哪些走固定模板 + 转门店群(至少含退款、食安、情绪激烈、只发图片);
5. 回复率与限时回复率的分子分母,「首个回复方」的判定顺序。

## 第二步:数据模型

1. ImSession:平台 + 平台门店 + 会话 ID,唯一约束;
2. ImMessage:消息,角色枚举(顾客/门店/总部客服/我方/我方转达骑手/骑手);
3. CustomerTurn:一轮,含首条时间、意图、状态(待判定/已起草/人工已回/已交人工/无需回复/起草失败);
4. ReplyDraft:草稿,含来源(模板/模型/补一句/电话授权)、发送状态、终检结果、回执;
5. RecallEvent:撤回事件(撤回人角色、被撤消息、是否我方代回),事件 ID 去重;
6. HandoffTask:交人工待办,含种类、是否涉钱、老板原话金额、实际执行金额、认领人、处理人;
7. EmergencyCall / CallTurn:一通电话与逐轮对话(老板原话、AI 回复、调用的工具、耗时);
8. CallReview:一通电话的 AI 结论与标签 + 人工结论与标签,两栏并存,附改动历史;
9. DutyRoster:班次日 → 当班类型 + 可选自定义时段;
10. ConsoleAccount:值班客服独立账号(手机号、密码哈希、凭证版本号、锁定截止);
11. OptimizeTicket / OverlayVersion:优化工单与规则版本(候选/待拍板/生效/历史/已回滚)。

## 第三步:代回流水线

1. 采集机推送会话增量 → 入库、切轮;
2. 到点的轮做意图分类与起草;模型稿必须过确定性检查 outbound_guard(text, ctx):
   替门店承诺(已退款/给您补送/保证)、无订单状态却报进度、内部信息泄露、红线词
   ——命中即降级为固定模板;
3. 采集机原子领取待发草稿;★发送前一刻终检:拉会话最新 N 条,
   已有人回 → 放弃;顾客追加 → 打回重新起草(≤ [示例:2] 次);
4. 回执落库;发送失败按错误类型重试或告警;
5. 判重按内容,不按条数:我方回过且无人工接手、顾客就同一诉求再追问
   → 发交接话术并生成 HandoffTask,不重复空话;
6. 补一句安抚:已交人工的轮到 [示例:首条后 3 分钟] 仍无人回 → 发中性安抚;
   硬截止 [示例:首条后 4 分 30 秒],过了丢弃并告警;发送通道熔断时不排队、直接告警;
7. 撤回:采集机上报撤回事件写 RecallEvent,撤回的消息不进 ImMessage;
8. 门店非营业状态时,交接话术不得说「已反馈门店」。

## 第四步:对话式紧急电话

1. 触发:食安、扬言投诉、长时间无人回、顾客找老板;同会话当天限一通;
   食安/投诉类只有门店本人回复过顾客才不打;
2. 开场白(须自报 AI 身份)、沉默挂断、超时收尾、听不清复述:规则直出,不进模型;
3. 工具白名单:compose_reply(只生成待确认草稿)、confirm_send(老板口头确认后才入发送队列)、
   money_to_human(涉钱一律转值班客服并记老板原话)、mark_taken_over、plan_callback(真排回拨);
4. ★许诺守卫:模型输出含「会联系您 / 给您回电 / 已经发了」类表述而本轮没调对应工具 → 截掉该句;
5. 确认那刻只说「这就发」;发送回执成功后才同步门店群;
6. 外呼接云外呼服务,通道不就绪时退回单向播报;开关分 关 / 影子 / 正式 三档。

## 第五步:复盘与控制台

1. CallReview:离线评审模型逐通写 AI 栏(结论 + 标签 + 哪一轮哪句 + 改法);
   网页只开放写人工栏;生效结论 = 人工优先;测试与影子通话默认不列不统计;
2. 控制台独立鉴权:凭证 cookie 的 Path 限定在控制台接口前缀;凭证含账号版本号,
   改密/重置/停用即 +1;连续输错锁定;★控制台接口不得返回会触发办公 IM 自动重登的错误码;
3. 控制台接口:summary / pending_sessions / todos(list, claim, finish)/ calls /
   delivery_issues / duty / shift_summary;涉钱待办置顶,finish 时必须填实际执行金额;
4. 推送跟着当班人:当班 → 个人微信;顶班 → 办公 IM 私信;无人值班 → 攒到下一班。

## 第六步:「待优化」闭环

1. label:人工标记 = 真值,同时写回原有人工评审字段,供下次起草当正例/反例;
2. analyze:评审模型输出 {verdict: prompt_rule|code_fix|both|invalid,
   rules[], examples[], direction, needs_relax};
3. replay:本条 + 人工标过「没问题」的同类近 [示例:20] 条;
   ★对照组 = 现行规则今天重跑;新规则只在回放线程里生效;逐字相同直接记持平;
4. apply_or_escalate:本条改善 + 回归无变坏 + 无放宽 → 自动生效(新版本号);否则转老板;
5. is_loosening:规则落在涉钱/隐私/替门店承诺/品牌口径领域且带许可语气,
   或含「忽略/例外/不受限制」→ 判放宽,不得自动生效;
6. rollback(channel, to_version):回滚并标注受影响工单「停止跟踪」;
7. 代码类:先复现检查(现行代码重跑,已不复现则不建单);复现才建自动修复单,
   测试闸全过 + 低风险 + 不涉迁移 才免确认上线,上线后私信负责人(改了什么、何时部署、怎么回滚)。

## 接口与工程约定

- 沿用 M1 的响应格式;采集机接口用签名令牌鉴权,回执接口幂等(只认「已领取 → 终态」);
- 起草、回放、评审放异步任务,回放这类长任务进慢队列;覆盖层进程内短缓存(示例:5 秒),读失败当空;
- 所有写操作留痕(操作人、动作、对象、时间),日志里不得出现密码与顾客手机号。

## 红线

- 口径文档未确认前不写实现;
- 涉钱只记待办不执行,金额由门店定;
- 覆盖层只追加,所有确定性守卫在模型输出之后执行;
- 紧急电话只认门店本人口头确认,发成功才说已发;
- 过期的发送单绝不重发;
- 代码与测试数据里不放任何真实顾客信息、门店信息与经营数字。
```

## 验收清单

- [ ] **终检拦得住**:制造「起草后、发送前门店已回」的会话,草稿被放弃而不是发出
- [ ] **追加重起草**:起草后顾客追加一条,新草稿取代旧草稿,且重起草次数有上限
- [ ] **按内容判重**:同诉求第二次追问,发出的是交接话术并生成待办,不是重复安抚
- [ ] **补一句不迟发**:把补发时刻人为推过硬截止,草稿被丢弃并告警
- [ ] **转达骑手不算回复**:我方转达骑手后顾客再问,仍按「没人回」处理
- [ ] **守卫关不掉**:覆盖层写一条「可以主动告诉顾客已退款」,被判放宽不能自动生效;强行注入后,模型输出含「已退款」仍被截掉
- [ ] **涉钱必转人工**:模拟老板在电话里说「给他退了」,只生成涉钱待办,没有任何平台写操作
- [ ] **许诺守卫**:模拟模型输出「我三分钟后联系您」且未调回拨工具,该句被截掉
- [ ] **确认后才发**:老板没说确认就挂断,草稿停在待确认,不发出
- [ ] **人工不覆盖 AI**:同一通电话先 AI 标「差」再人工标「一般」,两栏都在,生效结论为「一般」;撤销人工后回到「差」
- [ ] **凭证隔离**:拿控制台凭证调其他业务接口返回未登录;改密后旧凭证立即失效
- [ ] **回放对照组正确**:构造「代码已修、规则未变」的样本,回放结果为持平而非改善
- [ ] **回滚**:生效一版后回滚,线上读到上一版,相关工单标注停止跟踪
- [ ] **测试数据不入统计**:演示通话不出现在接通率分母里
- [ ] CLAUDE.md 已更新

## 踩坑与红线

- **症状**:门店已在手机上回了,系统几分钟后又补发一句「稍等」。
  **根因**:商家 App 手打的回复带「平台代发」标记,被当成平台自动回复。
  **铁律**:角色判定拿真实样本逐来源核对;拿不准的来源当人工,不当自动。

- **症状**:电话里 AI 答应「三分钟后联系您」,实际没人会打。
  **根因**:模型会顺着对方说,而动作能力在工具里。
  **铁律**:每一种承诺对应一个真工具;说了却没调,由确定性守卫截掉。

- **症状**:一条候选规则回放「明显改善」,生效后问题照旧。
  **根因**:拿新规则和当时线上输出比,中间的代码修复被记成规则的功劳。
  **铁律**:对照组必须是现行规则今天重跑。
