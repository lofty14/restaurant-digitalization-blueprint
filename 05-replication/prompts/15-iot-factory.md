# M7 冷链温控与工厂 IoT

> 本页是复刻路线图 M7 阶段的第三篇 prompt:把冷库和车间的温度数据自动采回来、做成有门禁的告警、并接进批次追溯。适合有中央工厂或自有冷链、要过食品安全体系审核的团队,以及他们的 AI 编程助手。

## 读完你会知道

- 采集任务的四件套:节流、重叠窗口、空值容错、零结果告警
- ★告警门禁怎么写进 prompt——这是本模块唯一「不做就白做」的设计
- 温度怎么挂进批次追溯,粒度不对会发生什么
- 一份验收清单,重点验的是**采集悄悄停了会不会有人知道**

## 目标

- 定时从设备厂商云拉取温度数据,落到**自己的库**;
- 越限判定 + **门禁**决定告警发不发,曲线数据始终完整;
- 限值、误差带、点位映射全部页面可配;
- 温度按生产组织粒度归集,可挂到批次上供追溯查询;
- 来料验收温度数值化,并与自动采集对拍。

背景模式篇见[冷链温控与工厂 IoT:让设备自己说话](../../02-modules/iot-coldchain.md)。

## 喂给 AI 的指令

整块复制给你的 AI 编程助手,先替换方括号占位符。

```markdown
你要在现有 Django 单体项目里新增一个「冷链温控 / 工厂 IoT」模块,
数据来自第三方设备云的 HTTP API(设备型号与厂商由我方提供,你只按通用方式对接)。

## 第一步:模型

1. 采集点位(Probe):点位编号、名称、所在区域/工位、设备类型、用途、
   温度上下限、误差带、观察期起止、是否启用;
2. 温度记录(TempPoint):点位、采集时间、温度值、湿度值、来源(实时/补传)、
   唯一约束 (点位, 采集时间) 用于去重;
3. 告警记录(TempAlert):点位、时间段、越限类型、是否发送、**未发送原因**、处理状态;
4. 采集运行日志(PullLog):任务开始/结束时间、拉取条数、错误信息。

## 第二步:采集任务(★四件套必须齐)

写一个定时任务,按 [示例:每 10 分钟] 执行:

1. **节流**:token 获取要缓存并设最小间隔;拿到限流类错误码时**直接中断本轮**并记日志,
   不要重试到把配额刷光;
2. **重叠窗口**:每次拉取「上次成功结束时间 − [示例:30 分钟]」至今,靠唯一约束去重,
   以捕获设备补传的迟到数据;
3. **空值容错**:单个点位返回空值或异常时跳过该点位,继续拉其余点位,不中断整轮;
4. **零结果告警**:一轮下来所有请求都成功但入库条数为 0,**必须记为告警**——
   「成功但为空」是最隐蔽的失败模式,不能只在异常时告警。

主通道优先使用实时数据接口;历史查询接口作为补数通道(部分厂商云对新设备的
历史接口会返回空,不要默认它可用)。

## 第三步:★告警门禁

越限判定之后,发不发通知由门禁决定,三个条件全满足才发:
- **有货**:该区域/库当前有在存批次;
- **有工序**:当天该区域有排产或报工记录;
- **过观察期**:点位不在启用/调整后的观察期内。

不满足时,把告警记录下来并写明**未发送原因**,便于回溯。

★铁律:**门禁只作用于通知,不作用于采集**。温度曲线必须完整落库,
体系审核要看的是全量数据,不是筛过的数据。

## 第四步:配置化与页面

- 限值、误差带、观察期、点位与区域/工位的映射,全部在页面上配置,
  **禁止写死在代码或前端**;前端的误差带从后端配置读取,不留第二份真相;
- 提供温度曲线页(按点位/区域/时间段查询)与告警列表页(含未发送原因)。

## 第五步:接进追溯与来料验收

- 温度日志按**与生产组织一致的粒度**归集([示例:按工位]),
  生产报工时把该工位该时段的温度区间快照到批次上;
  ★粒度不一致会导致追溯页面永远为空,实现前先确认生产侧是按什么组织的;
- 来料验收表单增加**数值型**中心温度字段 + 品类限值配置,超限必须填写处置措施;
- 定时对拍:同时段的人工填写温度与自动采集温度偏差超过 [阈值] 时告警。

## 接口与工程约定

- 沿用 M1 的响应格式、鉴权与定时任务框架;
- 所有对外部云的调用要有超时、重试上限与熔断,失败信息落 PullLog;
- 采集任务必须可安全重跑(依赖唯一约束去重)。

## 红线

- 第三方云的数据必须落到自己的库;
- 门禁不得影响数据完整性;
- 参数一律配置化;
- 追溯粒度对不齐时**宁可留空**,不许猜一个近似值填上。
```

## 验收清单

- [ ] **重叠窗口生效**:构造一批迟到 20 分钟的补传数据,下一轮拉取能把它们收进来,且不产生重复行
- [ ] **限流处理**:模拟限流错误码,任务中断并记日志,不产生连续重试风暴
- [ ] **空值容错**:让一个点位返回空值,其余点位数据照常入库
- [ ] **零结果告警**:让接口全部返回 200 但无数据,系统产生告警
- [ ] **门禁生效**:空库(无在存批次)状态下制造越限,曲线有数据但没有通知,告警记录里写明未发送原因
- [ ] **门禁不影响数据**:上一条场景中,温度曲线页能看到完整数据
- [ ] **配置化**:在页面上改一次限值和误差带,前后端立刻一致,无需发版
- [ ] **追溯挂载**:完成一次报工后,该批次能查到对应时段的温度区间
- [ ] **来料温度**:验收表单不填数值无法提交;超限时必须填写处置措施
- [ ] **手测对拍**:构造一个人工填写值与自动采集偏差过大的场景,系统告警
- [ ] CLAUDE.md 已更新

## 踩坑与红线

- **症状**:告警群里天天报异常,没人再看。
  **根因**:空库降温、无排产、刚开机这些正常状态被当成异常。
  **铁律**:门禁三条件;告警的价值 = 命中率 × 被看见的概率。

- **症状**:曲线空白好几天,期间零告警。
  **根因**:只在请求异常时告警,而失败模式是「全成功、零数据」。
  **铁律**:零结果本身就是告警条件。

- **症状**:加工段的追溯页面永远是空的。
  **根因**:温度按区域记录,而生产按工位组织。
  **铁律**:追溯粒度必须与生产组织粒度一致。
