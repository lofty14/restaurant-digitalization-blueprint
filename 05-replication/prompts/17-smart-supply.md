# M8 智能采购与排产

> 本页是复刻路线图 M8「AI 接管一线」阶段的第二篇 prompt:把补货口径的结果变成每天的采购与排产草稿,让人只看拿不准的行,再按品逐个放权给系统自动下单,并用偏差问因闭环迭代规则。适合已建成补货链路与生产工单、「每天人工下单」已成为瓶颈的团队,以及他们的 AI 编程助手。

## 读完你会知道

- 施工顺序:先草稿、再分级、再影子、最后放权——每一步都能停在原地
- 哪些闸必须在 prompt 里写死:急单豁免、黑名单落库、件与千克的换算、金额上限
- 采购群机器人的三道代码级门禁,为什么不能交给提示词
- 一份验收清单,重点验的是**系统下错单之前会不会被拦住**

## 目标

- 每天定时生成按供应商分组的**采购草稿**与按品的**排产草稿**,人确认才成单;
- 草稿行分级,推送只推异常与提示,正常行一键确认;人的修改自动回写成参数,可回滚;
- 按品资格白名单「关 → 影子 → 开」,带单张、单日金额上限与总闸;
- 每天比对建议与实际,问原因、出周报;可选:需求预测影子列、供应商评分卡、采购群机器人。

背景模式篇见[智能采购与排产:从每日草稿到按品放权](../../02-modules/smart-supply.md),建议先读再喂 prompt。

## 喂给 AI 的指令

整块复制给你的 AI 编程助手。方括号内的占位符先替换成你的实际参数;标「示例」的数字只是起点,按自己的业务定。

```markdown
你要在现有 Django 单体项目里新增「智能采购与排产」模块。按下面的顺序施工,
每一步做完先自检再进下一步。

## 第一步:口径文档先行
先产出「采购与排产自动化口径文档」,交人类确认后再写代码。必须写清:
1. 本模块不重算任何上游口径:日均、提前期、在途、安全天数、净需求一律调用补货模块的唯一出口;
2. 建单只走两个核心函数 place_purchase_order() / place_work_order()
   (从现有建单视图抽出,不碰 request;页面、机器人、定时任务共用);
3. 所有阈值的默认值与配置位置:微量过滤 [示例:半天用量]、忽略静默 [示例:默认5天,上限10天]、放权窗口 [示例:30天]、
   影子期 [示例:10天]、影子偏差 [示例:20%]、单张与单日金额上限 [你的金额]、每天自动工单上限 [示例:5张]。

## 第二步:数据模型(不加外键,靠业务键关联)
1. SupplyRule(供应商, 商品):起订量、订货倍数、货源紧张度、是否首选、
   采购周期天数(一次买够几天)、提前期(历史实测高分位回填,人工值不覆盖)、改量系数;
2. BuyDraft(业务日, 供应商, 状态, 来源) + BuyDraftLine:建议量、凑整前原始净需求、
   规则备注、采购大类快照、grade(0正常/1提示/2异常)+ 原因列表、单价与单价来源;
3. MakeDraft(业务日, 商品) 一天一品一行:建议产出件数、投料千克、系统原建议投料快照(确认不覆盖)、
   缺料备注、状态(待确认/已建单/已忽略/已过期/拦截)、拦截原因;
4. BuyPolicy:按「原料/辅料/外购」三板块各一行:当班周几、每月固定日、近期已采购天数、
   跌破下限补量方式、静默天数;
5. AutoGrant(类型, 商品, 供应商):档位 off/shadow/on、资格指标、影子起始日、人工覆盖与原因、历史;
   AutoShadow(类型, 业务日, 商品, 供应商):会下的量与金额、实际量、偏差、是否定稿;
6. PlanGap:单列唯一键「类型:日期:商品:供应商」(不在可空列上建联合唯一),偏差类型、原因、状态;
7. TuneLog:自动调了哪个参数、旧值新值、证据、是否已回滚。

## 第三步:采购草稿引擎(每天清晨定时)
- 净需求 × 改量系数 → 起订量、倍数凑整;没配倍数的默认向上取整到整件;
- ★顺序:先微量过滤(用凑整前的原始量判),再凑整;
- ★采购周期只替换「补到天数」,不参与「出不出这一行」的判定;安全天数是地板;
- 降噪闸:忽略记忆(键=(供应商,商品),按忽略理由分档静默,「换供应商/数据错」不静默)、
  非当班日、近期已采购(默认关);
- ★急单豁免:跌破人工库存下限,或「有真实库存台账且可撑天数 < 提前期」→ 任何闸都压不住;
  ★库存台账为 0 不算急单(那是没有信号);
- ★被压掉的行逐条点名,写进当天告警与推送卡片的固定段落,不只记计数;
- 策略参数:某板块从没保存过 → 现算默认值返回并标 is_default,绝不建空种子行。

## 第四步:排产草稿引擎
- 需求件数 → 每件净重(包装换算阶梯)→ 产出千克 → ÷ 出成率 → 投料千克;
  ★件数绝不能直接当千克用;折不出来进拦截;
- 缺料预检只写备注,不拦截、不倒推少排;
- 拦截(黑名单):无配方档案 / 出成率缺失或 ≤0 / 配方与实际耗用偏离 ≥[示例:3倍]
  且样本 ≥[示例:3张完工单] / 量纲折不出 → 照样落库、状态=拦截、写原因;确认接口拒绝,绝不自动建单;
  ★样本不足时只标红并降为不可一键确认,不拦截;
- 白名单开关只认按品行;仓维度或全局默认行上的开关一律不生效,保存时直接拒绝。

## 第五步:分级、一键确认与参数回写
- grade_buy_line() / grade_make_row() 两个纯函数给每行定级;历史查不到时「首次出现」「偏离历史」不判;
- 推送卡片顶部一句总数,只逐行列提示与异常;
- bulk_confirm_normal(dry_run=True 先预览):按供应商把正常行建单,剩余行挪进同供应商的新草稿;
- 忽略必须选结构化原因(下拉枚举,「其他」须备注);
- 回写:同向改量 ≥[示例:4次中3次] 且幅度 ≥[示例:20%] → 调改量系数(钳在 [示例:0.3~2.0],
  只用上次调整之后的确认样本);以「低频」忽略多次 → 拉长采购周期;
  ★只认结构化原因,不读老自由文本;每条调整可回滚,当前值已被人改过则拒绝回滚。

## 第六步:放权白名单
- 每天在排产、采购草稿之前跑 review_grants():先把到期的影子行与人的实际单比偏差并定稿,
  再按窗口重算资格,再流转 off → shadow → on;任一天不达标 → off 且影子期清零;
- shadow 档只写 AutoShadow,不建任何单;on 档只处理 grade==0 的行;整张都可自动就整张确认,部分可自动就先拆出新草稿再确认,失败则并回;
- ★安全阀:单张超上限,或当日累计将超上限 → 整张留草稿并在群里提醒;付款账户定不了 → 转人工;
- 人工强制开或关必须填原因并留历史;总闸关 = 连影子都不记。

## 第七步:偏差问因
- 每天傍晚:复算昨天(纠正晚确认的草稿)→ 比对今天 → 汇总一张卡片问原因;
- 偏差分五类:无建议却下了单 / 实际比建议多或少(量差超 [示例:15%])/ 草稿被忽略 /
  到期无人处理 / 系统压掉人却做了;
- ★覆盖闸:近 [示例:45天] 从没进过草稿的品,落库但标「无需问」,周报单列「覆盖缺口」;
- 群里回复解析顺序:「原因 编号 原因词」→ #编号 → 品名 → 回复了只含一条的卡片;都不中就不回执;
- 只写偏差表、只发内部群,不改任何草稿与单据;周一出「类型 × 原因」周报与规则迭代建议。

## 第八步(可选):需求预测影子列与供应商评分卡
- 预测 = 去年同周店均 × 店均趋势 × 当前下单门店数 × 节假日系数,出中位与高分位两档;
  近期归零的品先判停卖再走同比;原料不出数,草稿上显示「—」;
- 每周顺序:回填上周实际 → 算误差 → 重算新一批;中位数与高分位分别用各自的指标评;
- 喂采购的开关 forecast_feeds_buy 默认 False,打开前须回测并线上自评满 [示例:10周];
- 评分卡按「供应商 × 品类 × 月」:质量、交付、价格权重可配;缺指标退出加权,不按 0 分;
  出成率只在主料全来自同一家时归因;价格按同品涨幅加权;往月不重算;月报只发内部。

## 第九步(可选):采购群机器人
- 群与供应商的绑定只由人工写;群名相似度只排候选;唯一例外:群名模板内嵌供应商编号,
  且改群名的人是我方员工;
- supplier_id 与「发言人是否我方员工」由服务端在工具执行前注入,并覆盖模型传来的同名参数;
- 写操作两段式(复述 → 「确认」),仅我方员工可用(标记发货除外);按消息号去重;
  免 @ 确认窗口按(群, 发言人)隔离;改单加并发锁;
- 发票:金额按「分」比对,单张唯一精确命中或子集和唯一解才自动登记,其余只报候选;
- 送货单:必须「引用图片 + @」才触发;品名匹配两道闸 [示例:≥70分且领先第二名≥15分];
  不做单位换算;我方员工确认才建单;推群文案不带金额与「货源紧张」标记。

## 接口与工程约定
- 沿用 M1 的响应格式与鉴权,本模块挂采购管理权限;定时任务异常只记日志不打断整轮;
- 推送前做环境守卫(非生产只打印不发);推送开关分推内部群、推供应商群两个,出厂都默认关;
- 推送开关不影响已按品授权的自动下单,两者是两回事。

## 红线
- 口径文档未确认前不写实现;草稿引擎不重算上游口径,建单只走核心函数;
- 急单不被任何闸压住,被压的行必须可见;拦截行落库可见,绝不自动建单;
- 放权只按品、只碰正常级行,有金额上限与总闸;
- 不在代码与测试数据里放任何真实经营数字与供应商名称。

## 收尾
更新给 AI 看的项目说明文件与口径文档:写明降噪闸与急单豁免、拦截四类、
放权三档与安全阀、偏差覆盖闸,以及「台账为 0 不是急单」这条铁律。
```

## 验收清单

- [ ] **急单穿透**:给某品配很长的采购周期并刚忽略过它,再把库存压到人工下限以下,次日草稿照出
- [ ] **先过滤再凑整**:构造净需求不足过滤阈值、但起订量很大的行,它不出现在草稿里
- [ ] **被压的行可见**:被忽略记忆或非当班日压掉的品,在推送卡片的固定段落里逐条点名
- [ ] **台账为 0 不算急单**:无库存台账的辅料不被判急单,忽略记忆对它照常生效
- [ ] **拦截可见**:删掉某品的出成率,次日草稿里它以「拦截 + 原因」出现,确认接口拒绝
- [ ] **量纲正确**:手算「件 × 每件净重 ÷ 出成率」,与草稿投料千克一致,而不是等于件数
- [ ] **影子不建单**:某品处于 shadow 档,当天没有任何自动单,影子记录多一行
- [ ] **安全阀**:把单张上限调到低于草稿金额,整张留在待确认并收到提醒
- [ ] **降级**:影子期内造一天不达标,该品退回 off 且影子天数清零
- [ ] **回滚保护**:系统调整某参数后人又手改了它,回滚请求被拒绝
- [ ] **覆盖闸**:从未进过草稿的品被手工下单,偏差落库为「无需问」且不推卡片
- [ ] **预测盲区**:原料行的预测列显示「—」而不是 0
- [ ] **采购群门禁**:用 A 家的群查 B 家的单号,只回「不属于贵司」且不带任何字段;非员工发「确认」不建单;同一条「确认」回调重投两次只建一张单
- [ ] **发票唯一解**:两张同额待开票采购单时,发票不自动登记而是报候选
- [ ] **送货单近似平局**:两个候选品名得分接近时,该行进「认不出的行」而不是被猜一个
- [ ] 项目说明文件与口径文档已更新

## 踩坑与红线

- **症状**:降噪闸让草稿明显变短,业务看草稿上没有,很容易当成「不用买」。
  **根因**:被压掉的行只记了一个计数,没有展示。
  **铁律**:压行的闸必须与「今天压了哪些、为什么」的展示同批上线。

- **症状**:降噪闸几乎一行都没压下去。
  **根因**:很多料没维护库存台账,账面恒为 0,可撑天数为 0,于是全员被判急单。
  **铁律**:台账为 0 是没有信号,不是紧急信号;急单判据要求有真实台账。

- **症状**:某品的排产草稿连续多天被拦截、次日过期,直到断货。
  **根因**:配方偏离只有一张完工单做样本,那张单录错一次就造出几倍偏离。
  **铁律**:样本不足只标红不拦截;拦截是最贵的动作,证据要配得上它。
