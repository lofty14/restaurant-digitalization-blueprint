# 附录:技术施工图

> 这一层和前面五层**写法不同**。正文(01~05)是纯自然语言方案,刻意不放代码——方案与技术栈解耦,换语言换框架都成立。
> 附录收的是少数几份**需要精确到接口契约才能落地**的东西:表结构、端点契约、状态机、伪码。
> 它们仍然**不是本项目的产品源码**,而是通用示例——照着能写出你自己的实现。

## 为什么单开一层

有些方案的价值恰恰在细节里。比如"IM 里 @ 一个机器人,它在你自己电脑上跑 AI 干活,再把成品发回群"——
这件事讲成散文谁都懂,但真要复刻,卡住人的是那些看不见的地方:并发领单怎么保证不撞、消息重推怎么幂等、
额度用尽算不算失败、产物怎么过滤才不刷屏。这类页面放进正文会破坏统一风格,单独收进附录最干净。

## 读法提醒

- 附录是**业务无关**的:整份文档不含任何行业、公司、业务逻辑,业务能力全部外移到可插拔的目录里。
- 附录里的伪码是**说明机制用的**,直接复制粘贴大概率跑不起来——它的用途是喂给 AI 编程助手,让它照着写出真的能跑的版本。
- 涉及第三方服务(IM 平台、AI 服务商)的做法,**以对方当时的官方文档与服务条款为准**,本文只记我们当时的实现方式。
